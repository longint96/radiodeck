# Radio Deck — портал для нескольких радиостанций

Один liquidsoap-процесс + один Icecast2 обслуживают **несколько независимых
радиостанций** (рассчитано на 5–20 одновременно). Портал позволяет создавать
станции и переходить в отдельную админку каждой.

## Архитектура — важно понимать перед установкой

Осознанный выбор в пользу простоты: **без Docker, один общий движок**.
Следствия:

- **Один порт Icecast на все станции.** Станции различаются не портом,
  а mount-точкой: `http://server:8000/rock-fm.mp3`, `http://server:8000/jazz.mp3`.
- **Перезапуск движка перезапускает ВСЕ станции разом** (на несколько секунд).
  Своей изолированной перезагрузки у отдельной станции нет — это плата
  за отказ от Docker/отдельных процессов на станцию. Если позже понадобится
  независимость станций друг от друга — естественный путь развития это
  контейнер (или хотя бы отдельный liquidsoap-процесс) на станцию.
- **Загрузка файлов в медиатеку и правка ID3/Vorbis-тегов перезапуска НЕ
  требуют** — liquidsoap следит за папкой станции (`reload_mode="watch"`)
  и подхватывает новые файлы налету.
- **Требует перезапуска:** создание/удаление станции, смена битрейта,
  режима воспроизведения, mount-точки, глобального порта или пароля
  источника Icecast.
- Каждая станция технически — независимый плейлист + `output.icecast`
  внутри одного liquidsoap-процесса, собираются циклом `list.iter` по
  списку станций (см. `liquidsoap/radio.liq`) — не копипаста блоков.

### Два уровня паролей

- **Пароль портала** (`PORTAL_PASSWORD` в `.env`) — создание/удаление станций,
  глобальные настройки (порт, пароль источника), а также вход в админку
  **любой** станции без знания её собственного пароля.
- **Пароль станции** — свой у каждой станции, задаётся при создании,
  меняется из её собственной админки. Открывает доступ только к этой
  станции (медиатека, теги, mount/битрейт/режим, restart общего движка).

## Быстрая установка — одним скриптом

Если ставите на чистый Ubuntu 24.04 и вас устраивают дефолты — весь
раздел «1–5» ниже можно заменить одной командой:

```bash
sudo apt-get update && sudo apt-get install -y wget unzip
wget -O radiodeck.zip "https://github.com/longint96/radiodeck/archive/refs/heads/main.zip"
unzip -o radiodeck.zip
sudo bash radiodeck-main/install.sh
```

`wget`/`unzip` нужны здесь только для того, чтобы вытащить сам `install.sh` из архива — на минимальном образе Ubuntu Server их может не быть из коробки. Дальше уже сам скрипт ставит все нужные пакеты (в том числе `unzip` — он использует его повторно, для другой временной распаковки внутри установки).

Скрипт сам: ставит системные пакеты, создаёт пользователя `radio`,
скачивает и распаковывает проект, генерирует **случайные** пароли (портал,
источник Icecast, admin Icecast — не `changeme`), правильно настраивает
`icecast.xml` (включая известную ловушку с `<logdir>` и симлинк вместо
копии — обе описаны в разделе «Диагностика»), проверяет `liquidsoap --check`
**до** включения автозапуска, запускает всё по очереди с проверкой на
каждом шаге и в конце печатает пароли на экран и сохраняет их в
`/root/radio-deck-credentials.txt` (права 600).

Настраиваемые параметры — через переменные окружения:

```bash
sudo INSTALL_DIR=/opt/radio-deck RADIO_USER=radiosvc PANEL_PORT=4000 ICECAST_PORT=8080 bash install.sh
```

Если медиатека должна с самого начала лежать на отдельном диске/точке
монтирования (а не рядом с кодом проекта) — `MEDIA_BASE_DIR` независим
от `INSTALL_DIR`:

```bash
sudo MEDIA_BASE_DIR=/mnt/storage/radio-media bash install.sh
```

| Переменная | По умолчанию |
|---|---|
| `INSTALL_DIR` | `/home/claude/radio-project` |
| `RADIO_USER` | `radio` |
| `PANEL_PORT` | `3000` |
| `ICECAST_PORT` | `8000` |
| `MEDIA_BASE_DIR` | `INSTALL_DIR/media` |
| `DOWNLOAD_URL` | ссылка на актуальный архив проекта |

Путь из `MEDIA_BASE_DIR` при установке — это лишь **начальное** значение;
дальше он живёт в реестре станций и меняется через портал (ENGINE
SETTINGS → MEDIA STORAGE, с автоматическим переносом уже загруженных
файлов), а не повторной установкой или правкой `.env`.

Скрипт откажется работать поверх уже установленного проекта (проверяет
`data/stations.json`), чтобы случайно не затереть рабочие станции —
для намеренной переустановки поверх существующей папки добавьте `FORCE=1`.

Если что-то пойдёт не так — скрипт останавливается на первой же ошибке
с понятным сообщением и командой для диагностики (`journalctl -u ...`),
а не продолжает после провала. Для тонкой настройки уже установленного
инстанса (создание станций, смена паролей и т.д.) дальше используйте
портал, а не повторный запуск скрипта.

## Ручная установка (если нужен контроль над каждым шагом)

## 1. Системные зависимости

```bash
# Ubuntu 24.04
sudo apt update
sudo apt install -y liquidsoap icecast2 nodejs npm ffmpeg

sudo useradd -r -m -d /home/radio -s /usr/sbin/nologin radio
```

> ⚠️ Проверьте версию: `liquidsoap --version`. Генератор конфигов использует
> записи (`{key=value}`) и `list.iter` — это стандартный liquidsoap 2.x
> (Ubuntu 24.04 из apt даёт 2.2.x, этого достаточно). Если у вас более старая
> версия без поддержки записей — см. раздел «Диагностика» в конце файла.

## 2. Разместить проект

```bash
sudo mkdir -p /home/claude/radio-project
sudo cp -r radio-project/* /home/claude/radio-project/
sudo chown -R radio:radio /home/claude/radio-project
```

> Путь `/home/claude/radio-project` — замените на реальный и синхронно
> поправьте во всех `.env`, `.service`-файлах и `systemd/radio-sudoers`.

## 3. Icecast2

```bash
sudo cp icecast/icecast.xml /etc/icecast2/icecast.xml
sudo systemctl enable icecast2
```

Замените пароли-заглушки в `icecast.xml` (`source-password`,
`admin-password`) на реальные **до первого запуска**. `source-password`
должен совпадать с тем, что портал хранит как глобальный пароль источника
(задаётся/меняется потом через ENGINE SETTINGS на портале — при первом
запуске возьмите то же значение, что вписали в `icecast.xml`).

```bash
sudo systemctl restart icecast2 && sudo systemctl status icecast2
```

## 4. Liquidsoap

```bash
sudo cp systemd/liquidsoap-radio.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable liquidsoap-radio
```

Пока не создано ни одной станции, `stations.liq` содержит пустой список —
движок стартует, но ничего не вещает. Это нормально.

```bash
sudo -u radio liquidsoap --check /home/claude/radio-project/liquidsoap/radio.liq
sudo systemctl start liquidsoap-radio
sudo systemctl status liquidsoap-radio
journalctl -u liquidsoap-radio -f
```

## 5. Backend-портал

```bash
cd backend
npm install
cp .env.example .env
nano .env   # PORTAL_PASSWORD и пути — обязательно поменять
```

### Права на перезапуск сервисов

```bash
sudo visudo -cf ../systemd/radio-sudoers
sudo cp ../systemd/radio-sudoers /etc/sudoers.d/radio-panel
sudo chmod 440 /etc/sudoers.d/radio-panel
```

Разрешает пользователю `radio` **только** перезапуск/статус `icecast2` и
`liquidsoap-radio` — не полный root-доступ.

### Запуск как systemd-сервис

```bash
sudo cp systemd/radio-panel.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now radio-panel
```

Портал будет на `http://<сервер>:3000`.

### Локальная разработка (без systemd)

```
SERVICE_MODE=process
```
в `.env` — тогда портал сам управляет процессом liquidsoap напрямую
(без sudo, без Icecast автоперезапуска — Icecast в этом режиме поднимите
вручную один раз, `restart` в этом режиме перезапускает только liquidsoap).

```bash
npm start
```

## 6. Использование

1. Откройте `http://<сервер>:3000` → экран портала → пароль из
   `PORTAL_PASSWORD`.
2. **ENGINE SETTINGS** — проверьте/задайте порт и пароль источника (должен
   совпадать с `icecast.xml`).
3. **+ Создать станцию** — название, mount (можно оставить пустым — соберётся
   из названия), битрейт, режим, пароль админки станции.
4. Нажмите **⟲ Перезапустить движок** (в блоке TRANSPORT) — новая станция
   начнёт вещать.
5. **Открыть админку** на карточке станции → `/station/<slug>` → вход по
   паролю станции (или паролю портала) → загрузка файлов, теги, mount/битрейт/
   режим, смена пароля станции.

### Слушать поток

```
http://<сервер>:<общий порт>/<mount станции>
```

Оба значения показаны на карточке станции в портале и в её собственной
админке (поле «Адрес для слушателей»).

## API — коротко

Портал (`X-Portal-Password`):
```
GET    /api/portal/stations
POST   /api/portal/stations            {name, mount?, bitrate, mode, password}
DELETE /api/portal/stations/:id?deleteMedia=1
GET    /api/portal/global
POST   /api/portal/global              {port?, sourcePassword?}
GET    /api/portal/status
POST   /api/portal/restart
```

Станция (`X-Station-Password` или `X-Portal-Password`), `:id` — slug или id:
```
GET    /api/stations/:id/settings
POST   /api/stations/:id/settings          {name?, mount?, bitrate?, mode?}
POST   /api/stations/:id/settings/password {oldPassword, newPassword}
GET    /api/stations/:id/library
POST   /api/stations/:id/library/upload    (multipart, поле "files")
DELETE /api/stations/:id/library/:filename
GET    /api/stations/:id/library/:filename/tags
PUT    /api/stations/:id/library/:filename/tags
GET    /api/stations/:id/control/status
POST   /api/stations/:id/control/restart   (перезапускает ОБЩИЙ движок)
```

## Редактирование тегов

MP3 — ID3v2 (`node-id3`). OGG/FLAC — Vorbis Comments через системные
`ffmpeg`/`ffprobe`, стрим-копированием (без переэнкодинга). WAV/AAC/M4A
пока не поддерживаются.

## Системный монитор и «сейчас играет»

На портале — блок **SYSTEM MONITOR** (CPU, память, место на диске под
`MEDIA_BASE_DIR`, обновляется каждые 10 сек). Память считается через
`/proc/meminfo` (`MemAvailable`), а не `os.freemem()` — Node-модуль `os`
на Linux трактует файловый кэш как «занятую» память, что вводит в
заблуждение почти всегда показывая память почти забитой.

На карточках станций — живой индикатор (● зелёный/красный) и текущий
трек. Источник правды — **не** статус systemd-сервиса (тот показывает
только «процесс жив», не «эта конкретная станция реально вещает»), а
`status-json.xsl` самого Icecast: если mount станции есть в списке
активных источников — она online, ICY-заголовок `title` — то, что сейчас
играет. Требования к этому:
- Icecast должен быть доступен на `localhost:<порт>` с самого сервера
  портала (обычно так и есть).
- Трек показывается, только если файл содержит теги (title/artist) —
  liquidsoap формирует ICY-title из метаданных трека; для файлов без
  тегов Icecast просто не пришлёт `title`, отобразится «в эфире» без
  названия.

## Длительность, битрейт и общая продолжительность медиатеки

В таблице медиатеки каждой станции — длительность и исходный битрейт
каждого трека (через `ffprobe`, тот же системный инструмент, что и для
Vorbis-тегов), плюс общая продолжительность всей медиатеки станции —
видна сразу в заголовке блока MEDIA LIBRARY на странице станции, без
необходимости скроллить длинную таблицу.

То же самое (кол-во треков + суммарная длительность) показывается и на
карточках станций на главной странице портала — через отдельный лёгкий
эндпоинт `/api/portal/library-stats` (не читает теги, только длительности,
поэтому дешевле полного списка медиатеки). Обновляется раз в минуту, а не
каждые 10 секунд как «сейчас играет» — состав медиатеки меняется редко,
незачем лишний раз дёргать `ffprobe` по всем станциям сразу.

Результат кэшируется в памяти процесса по времени изменения файла — при
неизменном файле повторный расчёт не нужен, `ffprobe` вызывается только
на новые/изменённые файлы. Кэш общий между страницей станции и карточками
портала: если админ уже открывал станцию, карточка на портале не потратит
время на повторный расчёт.

## Удаление всей медиатеки станции

В блоке MEDIA LIBRARY на странице станции — кнопка «Удалить всё из
медиатеки». Действие необратимо, поэтому защищено двойным
подтверждением: обычный диалог + обязательный ввод слова «УДАЛИТЬ» в
отдельном окне. Служебные временные файлы (`.tag-tmp-*`, создаются при
записи Vorbis-тегов через ffmpeg) не затрагиваются — только сами
аудиофайлы. API: `DELETE /api/stations/:id/library` (без имени файла —
удаляет всё, в отличие от `DELETE /api/stations/:id/library/:filename`).

## Смена пути медиатеки

В блоке **MEDIA STORAGE** на портале — путь к базовой директории всех
медиатек (у каждой станции своя подпапка `<slug>/` внутри неё).
Первоначально задаётся через `MEDIA_BASE_DIR` в `.env` (только при самом
первом запуске), дальше живёт в `data/stations.json` и меняется только
через это поле в портале, не правкой `.env`.

При смене пути backend **автоматически переносит** папки всех
существующих станций на новое место (`rename`, либо копирование с
удалением исходника, если старый и новый путь на разных файловых
системах) и **сразу перезапускает движок** — без этого liquidsoap
продолжил бы слушать старый, уже опустевший путь, и все станции
выглядели бы пустыми до следующего ручного перезапуска. Это единственная
настройка портала с таким поведением — везде в остальных местах restart
осознанно отложен на отдельную кнопку.

Особенности:
- Если на новом пути уже существует папка с именем какой-то станции —
  перенос для неё пропускается (во избежание случайной перезаписи чужих
  данных), об этом сообщается отдельной ошибкой в отчёте, остальные
  станции переносятся как обычно. Разрешить коллизию нужно вручную на
  сервере, затем повторить смену пути.
- Требует двойного подтверждения в интерфейсе (обычный диалог + ввод
  слова «ПЕРЕНЕСТИ») — операция необратима автоматическими средствами
  панели (старые папки удаляются после успешного переноса).
- Новый путь должен быть доступен на запись пользователю, от которого
  работает `radio-panel` (`radio` по умолчанию).

## Обработка звука (выравнивание громкости, защита от клиппинга)

В `liquidsoap/radio.liq` для каждой станции после crossfade добавлена
цепочка `normalize` (выравнивает средний уровень громкости тихих и
громких треков к единому целевому значению) + `compress` (сглаживает
пики, чтобы резкие громкие места не проскакивали в клиппинг). Оба —
стандартные операторы liquidsoap, применяются **на дефолтных настройках**
без указания конкретных параметров — сделано намеренно, чтобы не
рисковать нарваться на нестандартную сигнатуру аргументов на вашей
конкретной сборке liquidsoap (уже бывало с `getenv`, см. выше).

Применяется **только к реальному аудио** — до объединения с
тишиной-заглушкой на случай пустой медиатеки, иначе автоматическая
регулировка усиления пыталась бы «усилить» тишину.

Так как это правка общего `radio.liq` (единого на все станции — см.
architecture), изменение применяется ко **всем** станциям сразу после
следующего перезапуска движка, и, как и с любой правкой этого файла,
**обязательно** прогоните `liquidsoap --check` перед `systemctl restart
liquidsoap-radio`:

```bash
sudo -u radio liquidsoap --check /home/claude/radio-project/liquidsoap/radio.liq
```

Если после прослушивания на реальном эфире дефолтные настройки покажутся
недостаточными (например, недостаточно громко, или наоборот — слышны
артефакты компрессии) — можно потюнить целевую громкость и параметры
компрессора вручную (`normalize(target=..., radio)`,
`compress(threshold=..., ratio=..., radio)`), но делать это лучше уже
итеративно, слушая реальный результат, а не вслепую.

## История воспроизведения

Плитка **PLAYBACK HISTORY** на странице станции (слева от BROADCAST
SETTINGS) — последние 15 треков. Реализовано без изменения самого
liquidsoap-скрипта: backend в фоне (раз в 15 сек, независимо от того,
открыт ли портал в браузере) опрашивает тот же `status-json.xsl` Icecast,
что и для «сейчас играет», и при смене заголовка дописывает запись в
`data/history/<slug>.json`. Повторный опрос того же трека не создаёт
дублей — сравнение идёт с последней записанной записью.

- Хранится не больше 15 записей на станцию — старые обрезаются.
- Записи старше **3 суток** отсекаются автоматически при каждом чтении
  и при каждой новой записи — даже если станция долго не выходила в
  эфир и не было новых треков, устаревшие записи не зависнут в истории.
- Кнопка 🗑 в заголовке плитки — очищает историю станции полностью
  (`DELETE /api/stations/:id/history`), с подтверждением.

Ограничение: если трек играет короче ~15 секунд (интервал опроса), смена
может быть не замечена. Для обычных треков (от минуты и дольше) это не
проблема.

## Пагинация и поиск в медиатеке

Таблица медиатеки станции — по 20 треков на страницу, с живым поиском
(фильтр по названию, исполнителю и имени файла, без обращения к серверу
на каждое нажатие — весь список уже загружен одним запросом при открытии
страницы, фильтрация и постраничная разбивка происходят в браузере).
Статистика в заголовке блока (кол-во треков, общая длительность) всегда
показывает данные по **всей** медиатеке, а не только по текущей
странице/фильтру.

## Лимит размера загружаемого файла

По умолчанию — 1024 МБ (`MAX_UPLOAD_MB` в `.env`). Если стоите за nginx,
не забудьте поднять `client_max_body_size` **выше** этого значения (см.
раздел про nginx ниже) — иначе nginx отклонит файл ещё до того, как он
дойдёт до backend, с невнятной ошибкой браузера вместо понятного
сообщения от панели.

## Reverse proxy (nginx)

Если ставите портал за nginx — обязательно поднимите `client_max_body_size`
(дефолт nginx — 1 МБ, любая загрузка аудиофайла крупнее сразу словит 413).
**Важно:** это значение должно быть **больше**, чем `MAX_UPLOAD_MB` в `.env`
backend'а (дефолт — 1024 МБ) — иначе nginx срежет запрос раньше, чем
multer вообще увидит файл, и вы получите генерическую ошибку браузера
вместо понятного сообщения от панели:

```nginx
server {
    listen 80;
    server_name your-domain-or-ip;

    client_max_body_size 1100M;  # больше, чем MAX_UPLOAD_MB из .env (дефолт 1024)

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_request_buffering off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

## Безопасность до продакшена

- Замените все пароли-заглушки (`icecast.xml`, `.env`, пароли станций).
- Поставьте reverse-proxy (nginx) с HTTPS — заголовки `X-Portal-Password` /
  `X-Station-Password` идут открытым текстом при обычном HTTP.
- Ограничьте файрволом порт портала (3000), если он не должен быть публичным.
- `data/stations.json` содержит bcrypt-хеши паролей станций — не публикуйте
  этот файл, ограничьте права доступа (`chmod 600`).

## Диагностика

**`liquidsoap --check` падает на `radio.liq`.** Скорее всего версия
liquidsoap старше 2.0 и не знает записи (`{key=value}`)/`list.iter` в этом
виде. Проверьте `liquidsoap --version`; если версия действительно старая —
самый быстрый обходной путь — переписать генератор
(`lib/liquidsoapConfigGen.js`) так, чтобы `stations.liq` выводил не список
записей, а полностью развёрнутый блок `playlist(...) + output.icecast(...)`
на каждую станцию текстом (то, как было устроено в первой, одностанционной
версии этого проекта) — механически более многословно, но не требует
записей/`list.iter`.

**Новая станция создана, но не вещает.** Проверьте, что после создания
нажали «Перезапустить движок» — добавление станции требует перезапуска.

**Порт занят / Icecast не стартует.** `icecast.xml` и `global.liq` должны
указывать один и тот же порт — портал синхронизирует их сам при сохранении
ENGINE SETTINGS, но при ручном редактировании легко разойтись.

**`systemctl status icecast2` показывает `active (exited)` и «...done.»,
но `ps aux | grep icecast` пуст, порт никто не слушает, станции офлайн.**
Icecast2 в Debian/Ubuntu работает от системного пользователя `icecast2`,
а не `radio`. Если `<logdir>` в `icecast.xml` указывает на папку внутри
проекта (например `/home/claude/radio-project/logs`, которая принадлежит
`radio:radio`) — демон не может создать свои лог-файлы, падает молча сразу
после старта, а старый LSB init-скрипт всё равно бодро репортует «done»
независимо от реального результата. Проверьте:
```bash
grep logdir /etc/icecast2/icecast.xml   # или /home/claude/radio-project/icecast/icecast.xml, если это симлинк
ls -la /var/log/icecast2                # должно быть доступно на запись пользователю icecast2
```
Должно быть `<logdir>/var/log/icecast2</logdir>` — это значение уже
исправлено в шаблоне проекта (см. комментарий в самом `icecast.xml`), но
если вы обновляли проект **полной** синхронизацией всего корня (не только
`backend/`) до этого фикса — файл мог откатиться на старое значение.
Почините вручную и добавьте `icecast/icecast.xml` в список исключений
`rsync` при будущих обновлениях (наравне с `.env`/`data/`), если делали
в нём собственные правки — портал не трогает `<logdir>` автоматически,
только `<port>`, `<source-password>` и `<sources>`.
